Speed of numeric-2 relative to numeric.js

All measurements

Median time per call. Relative speed is numeric.js time divided by numeric-2 time, so numeric.js is 1×: 0.5× means numeric-2 takes twice as long, 2× means it takes half as long.

How these numbers are produced
  • Each case runs the same seeded random input through both libraries. Inputs are converted to each library's own types before timing (numeric-2 Vector/Matrix, numeric.js arrays or numeric.t for complex values). Wrapping the result is part of the timed call.
  • The timer warms up each call, picks a batch size so one batch takes about 25 ms (10–15 ms in a quick run), then records 15 batches (7 in a quick run). The chart shows the median; whiskers and the tooltip show the 25th–75th percentile range.
  • Before timing, both outputs are compared. "Match" means they agree to a relative tolerance of 10−8; eigenvalues are compared as unordered sets; LU outputs use different packed layouts and are not compared.
  • Server runs use bun run bench:bun and bun run bench:node; numeric-2 runs from source on Bun and from a bundled build on Node. This page runs the browser bundle and loads numeric.js 1.2.6 from jsDelivr.
  • numeric.js generates code with new Function while it loads. Pages whose Content Security Policy forbids eval cannot load it at all; numeric-2 has no such dependency. The browser card above reports which case applies here.
  • Machines vary and so does noise: treat relative speeds within about ±15% of 1× as a tie.
