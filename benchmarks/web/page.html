numeric-2 Benchmarks

How the TypeScript port compares with the original numeric.js and with two established JavaScript libraries, math.js and stdlib, calling each library's public API on identical inputs. Results come from server runs on Bun and Node, and from this browser if you run the suite here.

Read these numbers as indications, not absolute measurements.
  • Timings depend on the machine: its processor, its memory and whatever else is running. The server results here come from a single machine, or from shared CI runners, which are noisier still.
  • They depend on the runtime and its version. Bun, Node and each browser compile JavaScript differently, so the same code can rank differently from one to the next.
  • The libraries are designed differently. stdlib works in place on typed arrays, math.js converts and checks its arguments on every call, and numeric-2 wraps results in Vector/Matrix objects. Each case uses each library's idiomatic API, so part of every difference comes from the API style, not just the algorithm.
  • Repeated runs vary. Treat differences within about ±15% as a tie, and look at the 25th–75th percentile ranges in the chart and tooltips.
  • The suite covers a chosen set of operations and sizes. Your workload may behave differently; run the suite in your browser, or on your own machine, to check.

How these numbers are produced
  • Each case runs the same seeded random input through every library that has the operation. Inputs are converted to each library's own types before timing: numeric-2 Vector/Matrix, numeric.js arrays (or numeric.t for complex values), math.js DenseMatrix, and stdlib Float64Array in row-major order. Producing a new result is part of the timed call; for stdlib's in-place BLAS routines that means allocating the output array.
  • math.js 15.2.0 is called through its documented functions; element-wise exp and sqrt use math.map, as math.js requires for matrices. stdlib is used through its standalone BLAS packages (@stdlib/blas-base-* 0.4.1), which run as plain JavaScript unless their optional native add-ons are compiled. stdlib publishes no general LU, solve, inverse, determinant or eigenvalue routines yet, so it is absent from those rows.
  • numeric.js solveQP is a port of quadprog that turned three of the Fortran original's "skip to the next iteration" jumps into early loop exits, so on some problems it returns an infeasible or suboptimal point; numeric-2's port keeps the original control flow and matches SciPy. Rows where this happens are marked as differing outputs.
  • math.js eigs fails to converge on the 24×24 and 48×48 random non-symmetric matrices used here; those cells show the error instead of a time.
  • The timer warms up each call, picks a batch size so one batch takes about 25 ms (10–15 ms in a quick run), then records 15 batches (7 in a quick run). The chart shows the median; whiskers and the tooltip show the 25th–75th percentile range.
  • Before timing, every output is compared with numeric-2's, which the test suite cross-validates against NumPy. "Match" means agreement to a relative tolerance of 10−8; eigenvalues are compared as unordered sets; LU outputs use different packed layouts and are not compared.
  • Some discrepancies are expected, for example where another library has a known bug. Each of these is declared in the benchmark definition with a written reason, and is shown as an accepted difference: hover over it, or select it, to read the reason. Any discrepancy without a declared reason is flagged in red.
  • Server runs use bun run bench:bun and bun run bench:node; numeric-2 runs from source on Bun and from a bundled build on Node. This page runs a browser bundle of numeric-2, math.js and stdlib, and loads numeric.js 1.2.6 from jsDelivr.
  • numeric.js generates code with new Function while it loads. Pages whose Content Security Policy forbids eval cannot load it at all; numeric-2 has no such dependency. The browser card above reports which case applies here.
  • Machines vary and so does noise: treat relative speeds within about ±15% of 1× as a tie.
